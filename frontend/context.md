# Frontend Context

Default Library and Compare pages are pre-rendered and prefetched by Next.js navigation links. Query selections use the same catalog via internal rewrites. The Backend health GitHub Action requests the production health endpoint every ten minutes on the default branch. Scheduled runner delays and free hosting quotas can still cause cold starts.

Library and Compare read the server-side catalog generated by the research export. Republish it after changing Supabase document summaries or financials.

Company cards use local logo assets, ticker aliases, and a shared building icon for unknown or unavailable logos. Motion uses short CSS transitions and honors reduced-motion preferences.

The November 2026 official-release expansion adds bundled logos for IBM,
Airbnb, Alphabet, Wipro, ICICI Bank, and Maruti Suzuki. Library, Compare,
and Research require a fresh committed `research-data` export to show new
companies, while document detail and chat use the live Supabase records.

Library groups disclosures by market and ticker in an alphabetical single-column
picker. Selecting a company reveals its latest snapshot and disclosure links
beside the picker. Compare uses the same picker independently in US and India
columns; direct `?us=...&india=...` links still seed the two selections.

The benchmark page also shows the expanded same-model pilot from
`research-data/expanded-same-model.json`. Its scores are calculated from the
recorded matched chunk IDs so the displayed figures stay tied to the source data.

Primary surfaces and actions use neutral black, charcoal, and silver. Market badges and risk states retain their semantic colors.

The research desk serves a published snapshot from Supabase. Run
`uv run --with numpy --with-requirements backend/requirements.txt python scripts/export_research.py`
after updating labels, documents, or extractions and commit both generated JSON files together.
Search uses a TF-IDF latent semantic index computed at export time. Filters restrict eligible
passages before ranking. Comparisons quote sentences from the matching passages. Research
routes need no live model call. Briefs are saved in this browser and export three highlights.

## Purpose

Next.js dashboard for browsing the disclosure benchmark, comparing US and India companies, viewing
risk/topic indexes, and asking retrieval-grounded questions.

## Key Decisions

- The dashboard reads data through the FastAPI API rather than directly from Supabase.
- The dashboard error state distinguishes a dead API from a healthy API with broken Supabase access,
  because `/api/health` can pass while document queries still fail.
- Document cards and detail pages surface source fidelity so users can tell full-transcript-derived
  India records from shorter curated summaries.
- Until the live Supabase table has the `source_fidelity` column, the UI falls back to `doc_id`
  (`_full_` means full transcript) so the distinction is still visible.
- The home page filters by source fidelity and counts distinct companies separately from
  disclosure records. Detail pages show financial-field coverage and an explicit pending state.
- New official release excerpts are labeled separately from paraphrased summaries; new
  sentiment results can come from a different model and must not be described by the existing F1.

## Gotchas

- `NEXT_PUBLIC_API_URL` must point at the deployed FastAPI service, not the frontend domain.
- Document-list failures often come from backend Supabase configuration or project availability,
  especially when the API process itself is still reachable.
